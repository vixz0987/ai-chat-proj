# Генератор синтетического датасета для профориентации

`generator/generator.py` создаёт синтетическую обучающую выборку для модели
профориентации: одна строка = один «прошедший опрос» абитуриент, по ответам
на вопросы чат-бота предсказывается кластер направления (K1…K12).

Нужен, пока нет размеченных реальных диалогов: даёт правдоподобные данные,
на которых можно проверить пайплайн и обучить baseline.

## Откуда берутся данные

Единственный источник истины — `data/Сценарий_вопросов_чат-бота.xlsx`
(листы «Вопросы» и «Варианты»). В нём у каждого варианта ответа проставлены
баллы кластерам, по ним и генерируются ответы. Меняешь сценарий — меняешь
только xlsx, код не трогаешь.

## Как устроена строка

| Колонка | Пример | Что внутри |
|---|---|---|
| `A2, A4, B1…F7` | `A2_10` | ID выбранного варианта ответа |
| мульти-выбор | `B1_opt1\|B1_opt4` | ID через `\|` |
| шкала | `4` | число 1..5 |
| `kw_K1…kw_K12` | `kw_K3=2` | сколько раз в текстовых ответах нашлись слова кластера K3 |
| `path` | `FULL` | маршрут диалога: FULL / SHORT / KNOWN / BROWSE |
| `target_cluster` | `K7` | ярлык — какой кластер в итоге «выбрал» респондент |

Пустая строка в ячейке — вопрос не задавался (не на маршруте или не прошёл
условие показа, как в реальном чате). Это норма, не баг.

## Как генерится

1. Случайно выбирается **таргет-кластер** (с весами: K1 чаще, K12 реже).
   С вероятностью 40% — ещё и «второй интерес» из смежных кластеров.
2. Для каждого вопроса варианты **взвешиваются по баллам кластера**, от
   имени которого респондент отвечает → ответы коррелируют с таргетом.
3. Добавляется **шум** (ответ наугад). Уровень зависит от маршрута:
   `KNOWN` тише (человек знает, чего хочет), `BROWSE` шумнее.
4. Текстовые вопросы (B9, C4, E2, E4) эмулируются как «разбор по ключевым
   словам»: в 70% в ответе нашлось слово своего кластера, в 20% — соседнего,
   в 10% — случайного. Считаются в `kw_K1…kw_K12`.

Именно поэтому в фичах есть сигнал — модель сможет выучить матчинг.

## Запуск

```bash
uv sync
uv run python generator/generator.py --check
```
--check в конце обучает контрольную модель и печатает accuracy / top-3
по каждому маршруту — это smoke-test, что пайплайн жив.

## Опции:

```bash
uv run python generator/generator.py --n 10000                # больше строк
uv run python generator/generator.py --out my.csv             # другой выход
uv run python generator/generator.py --xlsx path/to/scen.xlsx # другой сценарий
```

По умолчанию: 5500 строк, выход data/proforient_train_dataset.csv,
сценарий data/Сценарий_вопросов_чат-бота.xlsx.

## Встроенные проверки
Скрипт упадёт с assert, если нарушено: строк ≥ 5000, признаков ≤ 50,
ни один таргет >50% строк, уникальных таргетов ≤50% числа строк,
нет полных дублей. Это защита от случайной поломки датасета.

## Чего этот датасет не даёт
* Это синтетика. Accuracy 0.85 здесь ≠ 0.85 в проде: модель выучит
правила генератора, а не поведение людей. Для валидации настоящего
матчинга не годится — только как bootstrap.
* Текстов нет. kw_K* — счётчики попаданий ключевых слов, обратно
в «я люблю математику» не развернуть.
* path — почти утечка. В проде заранее неизвестен (определяется в
процессе диалога). Для честной оценки стоит обучить вариант без него.

## Требования
Python ≥ 3.10, pandas, numpy, openpyxl, scikit-learn (последний —
только для --check).
